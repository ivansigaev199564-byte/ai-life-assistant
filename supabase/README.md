# Серверная часть

Схема базы, политики доступа, гибридный поиск и две функции: разбор
голосовых заметок моделью Claude и генерация векторов для смыслового поиска.

Разворачивание отложено до момента, когда появится проект Supabase.
Всё, что нужно для этого, лежит здесь.

## Что внутри

```
migrations/
  0001_extensions.sql   pgvector, pg_trgm, unaccent и русская конфигурация поиска
  0002_tables.sql       семь таблиц сущностей плюс связи многие ко многим
  0003_rls.sql          политики доступа и триггеры версий
  0004_search.sql       полнотекстовые векторы, индексы поиска и синхронизации
  0005_embeddings.sql   таблица векторов, HNSW-индекс, функция hybrid_search
functions/
  parse-intent/         прокси к Claude со строгой схемой
  embed/                векторы через text-embedding-3-small
  _shared/              авторизация, CORS, схема разбора
```

## Развернуть

1. Создайте проект на supabase.com и поставьте CLI:

```
brew install supabase/tap/supabase
```

2. Свяжите локальную папку с проектом и накатите схему:

```
supabase link --project-ref ВАШ_REF
supabase db push
```

3. Задайте ключи моделей. Они живут только на сервере и в приложение
   не попадают:

```
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase secrets set OPENAI_API_KEY=sk-...
```

4. Выложите функции:

```
supabase functions deploy parse-intent
supabase functions deploy embed
```

5. Включите вход через Apple в разделе Authentication, Providers, Apple.
   Понадобятся Services ID и ключ из аккаунта разработчика Apple.

## Решения, которые стоит понимать

**Идентификаторы приходят с устройства.** Запись создаётся офлайн и должна
сохранить свой `id` после отправки: иначе связи между сущностями порвутся,
а повторная отправка создаст дубли.

**Удаление мягкое.** Устройство, которое было офлайн неделю, обязано узнать,
что запись удалена, а не воскресить её при следующей синхронизации.

**Версию и время изменения ставит база, а не клиент.** Часы на телефоне
могут отставать или уходить вперёд, и тогда разрешение конфликтов начнёт
выбирать неверную копию.

**Суммы в numeric, а не в числах с плавающей точкой.** Иначе сумма расходов
за месяц не сойдётся с суммой чеков.

**Функции работают от имени пользователя, а не сервисной роли.** Токен
вызывающего передаётся в клиент Supabase, поэтому политики доступа
продолжают действовать внутри функции: прочитать или записать чужие строки
нельзя даже при ошибке в коде функции.

**Гибридный поиск объединяет два метода через обратный ранг.** Полнотекстовый
поиск точен на дословных совпадениях, но не найдёт «потратил на еду»
по запросу «сколько ушло на обеды». Векторный понимает смысл, но путается
на именах и редких словах. Складывать их оценки напрямую нельзя: шкалы
несопоставимы, поэтому складываются позиции в выдаче.
